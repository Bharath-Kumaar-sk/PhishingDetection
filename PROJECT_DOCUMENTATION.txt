PROJECT OVERVIEW
================================================================================
This project implements a sophisticated phishing email detection system using
various Natural Language Processing (NLP) and Machine Learning techniques. The
system analyzes email text to classify emails as either "Phishing Email" or
"Safe Email".

The project demonstrates a progressive evolution of machine learning approaches,
starting from basic NLP techniques and advancing to state-of-the-art transformer
models, with hybrid approaches that combine multiple feature engineering methods.

DATASET
================================================================================
- File: Phishing_Email.csv
- Size: 52MB (approximately 18,000+ email samples)
- Features: Email Text, Email Type (Phishing Email / Safe Email)
- Purpose: Training and testing phishing detection models

TECH STACK & TOOLS
================================================================================

Core Libraries:
- Python 3.x
- pandas: Data manipulation and analysis
- numpy: Numerical computing and array operations
- scikit-learn: Machine learning algorithms and utilities
- NLTK (Natural Language Toolkit): Text preprocessing and NLP operations
- regex (re): Pattern matching for feature extraction

NLP & Embeddings:
- TfidfVectorizer: Convert text to TF-IDF weighted features
- Word2Vec (gensim): Pre-trained word embeddings (word2vec-google-news-300)
- DistilBERT (transformers): Transformer-based language model
- PyTorch: Deep learning framework for transformer models

Machine Learning Models:
- Logistic Regression: Primary classifier used across all approaches
- MultinomialNB: Naive Bayes classifier (baseline approach)

Feature Engineering:
- scipy.sparse: Efficient sparse matrix operations for combining features
- Custom pattern extraction: URLs, IPs, special characters, HTML tags

Text Preprocessing:
- Tokenization: word_tokenize (NLTK)
- Stopword removal: English stopwords (NLTK)
- Lemmatization: WordNetLemmatizer (NLTK)
- Regular expressions: URL removal, character filtering

================================================================================
                        PROJECT EXECUTION PIPELINE
================================================================================

The project follows a progressive development approach, where each Python file
represents an incremental improvement or alternative technique for phishing
detection. Below is the detailed explanation of each module in execution order:


1. BaseLineNLP.py - Baseline NLP Approach
================================================================================
PURPOSE:
Establishes a baseline phishing detection model using traditional NLP techniques
with TF-IDF vectorization and Logistic Regression.

APPROACH:
- Text Preprocessing:
  * Convert text to lowercase
  * Remove URLs and HTTP links
  * Remove non-alphabetic characters
  * Tokenize text into words
  * Remove English stopwords
  * Apply lemmatization to reduce words to base form
  
- Feature Extraction:
  * TF-IDF Vectorization with max 5000 features
  * Captures word importance based on frequency
  
- Model:
  * Logistic Regression (max_iter=1000)
  * Train/Test split: 80/20

KEY TECHNIQUES:
- TF-IDF (Term Frequency-Inverse Document Frequency)
- NLTK text preprocessing pipeline
- Logistic Regression classification

EXPECTED OUTPUT:
[Output will be captured after execution]


2. AdvancedNLP.py - Word2Vec Embeddings
================================================================================
PURPOSE:
Improves upon the baseline by using pre-trained Word2Vec embeddings to capture
semantic relationships between words.

APPROACH:
- Text Preprocessing:
  * Same NLTK preprocessing as baseline
  * Returns tokenized words (not joined string)
  
- Feature Extraction:
  * Loads pre-trained Word2Vec model (Google News 300-dimensional)
  * Converts each word to 300-dimensional vector
  * Calculates mean vector for all words in email
  * Handles out-of-vocabulary words gracefully
  
- Model:
  * Logistic Regression on 300-dimensional embeddings
  * Train/Test split: 80/20

KEY TECHNIQUES:
- Word2Vec pre-trained embeddings (gensim)
- Mean pooling of word vectors
- Semantic word representations

ADVANTAGES OVER BASELINE:
- Captures semantic similarity between words
- Better handles synonyms and related terms
- Dense representations vs sparse TF-IDF

EXPECTED OUTPUT:
[Output will be captured after execution]


3. Hybrid.py - TF-IDF Weighted Word2Vec
================================================================================
PURPOSE:
Combines the strengths of TF-IDF and Word2Vec by weighting word embeddings
with their TF-IDF importance scores.

APPROACH:
- Text Preprocessing:
  * NLTK preprocessing (returns joined string for TF-IDF)
  
- Feature Extraction:
  * Step 1: Fit TF-IDF vectorizer to get word importance weights
  * Step 2: Load Word2Vec embeddings
  * Step 3: Weight each word's vector by its TF-IDF score
  * Step 4: Calculate weighted mean of all word vectors
  
- Model:
  * Logistic Regression on weighted 300-dimensional embeddings
  * Train/Test split: 80/20

KEY TECHNIQUES:
- Hybrid feature engineering
- TF-IDF weighting of semantic embeddings
- Best of both worlds: semantic meaning + word importance

ADVANTAGES:
- More important words contribute more to email representation
- Reduces noise from common but uninformative words
- Maintains semantic relationships from Word2Vec

[Output will be captured after execution]


4. DistilBert.py - Transformer-Based Approach
================================================================================
PURPOSE:
Leverages state-of-the-art transformer models (DistilBERT) for deep contextual
understanding of email text.

APPROACH:
- Data Sampling:
  * Uses 2000 random samples for faster processing
  * DistilBERT is computationally intensive
  
- Feature Extraction:
  * Loads pre-trained DistilBERT model (distilbert-base-uncased)
  * Tokenizes text with DistilBERT tokenizer
  * Extracts [CLS] token embeddings (768 dimensions)
  * Batch processing (50 emails per batch)
  * Maximum sequence length: 128 tokens
  
- Model:
  * Logistic Regression on 768-dimensional BERT embeddings
  * Train/Test split: 80/20

KEY TECHNIQUES:
- Transformer architecture (DistilBERT)
- Contextual word embeddings
- [CLS] token as sentence representation
- Batch processing for efficiency

ADVANTAGES:
- Deep bidirectional context understanding
- State-of-the-art language understanding
- Captures complex linguistic patterns
- Better handling of context and word sense

5. BasicVersion2.py - Feature Engineering Approach
================================================================================
PURPOSE:
Enhances detection by combining TF-IDF text features with manually engineered
forensic features that capture phishing characteristics.

APPROACH:
- Manual Feature Extraction:
  * len_char: Email length in characters
  * n_urls: Count of URLs and web links
  * n_ips: Count of IP addresses
  * n_special: Count of special characters ($, !, %)
  * n_tags: Count of HTML tags
  * All features log-transformed with np.log1p
  
- Text Features:
  * TF-IDF vectorization (5000 features)
  * Standard English stopword removal
  
- Feature Combination:
  * Horizontally stack TF-IDF sparse matrix with manual features
  * Creates comprehensive feature set
  
- Model:
  * Logistic Regression with combined features
  * Feature importance analysis for manual features

KEY TECHNIQUES:
- Domain-specific feature engineering
- Pattern matching with regex
- Feature combination with scipy.sparse.hstack
- Log transformation for feature scaling

ADVANTAGES:
- Captures phishing-specific patterns (suspicious URLs, IPs)
- Combines statistical text features with forensic markers
- Interpretable feature importance

[Output will be captured after execution]


6. ErrorAnalysis.py - Model Introspection
================================================================================
PURPOSE:
Analyzes model errors to understand where the phishing detector fails and
identify patterns in misclassifications.

APPROACH:
- Same Feature Engineering as BasicVersion2.py:
  * Manual features + TF-IDF features
  
- Error Analysis:
  * Tracks test set indices
  * Stores predictions and actual labels
  * Identifies False Negatives (missed phishing emails)
  * Identifies False Positives (safe emails marked as phishing)
  * Displays example emails from each error category
  
- Output:
  * Total error count
  * First 5 false negatives with text snippets
  * First 5 false positives with text snippets

KEY TECHNIQUES:
- Error categorization
- Misclassification inspection
- Index tracking for sample retrieval

PURPOSE & VALUE:
- Understand model weaknesses
- Identify edge cases
- Guide future improvements
- Validate model reliability

7. RobustHybrid.py - Production-Ready Final Model
================================================================================
PURPOSE:
The most comprehensive and robust solution combining multiple feature types,
advanced text analysis, and live prediction capabilities.

APPROACH:
- Data Cleaning:
  * Removes extremely short emails (< 10 characters)
  
- Multi-Level Feature Extraction:
  
  A. Manual Forensic Features (log-transformed):
     * len_char, n_urls, n_ips, n_special, n_tags
  
  B. Word-Level TF-IDF:
     * 5000 features
     * Bigrams (1-2 word combinations)
     * English stopwords removed
  
  C. Character-Level TF-IDF:
     * 5000 features
     * Character n-grams (3-5 characters)
     * Captures misspellings and obfuscation (e.g., "P a y P a l")
  
- Feature Combination:
  * Stacks all three feature types (10,000+ features total)
  
- Model:
  * Logistic Regression on comprehensive feature set
  
- Live Prediction Function:
  * predict_new_email(raw_text) function
  * Processes new emails through full pipeline
  * Returns prediction and confidence probability
  
- Demo Tests:
  * Tests 3 sample emails with different characteristics
  * Displays verdict and confidence percentage

KEY TECHNIQUES:
- Multi-modal feature engineering
- Character n-grams for obfuscation detection
- Word bigrams for phrase patterns
- Production-ready inference pipeline
- Data quality filtering

ADVANTAGES:
- Most robust against adversarial attacks
- Detects character-level obfuscation (e.g., spaces in "PayPal")
- Comprehensive feature coverage
- Ready for deployment with prediction API
- Combines all best practices from previous approaches
